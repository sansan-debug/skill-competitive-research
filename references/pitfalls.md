# 操作雷区

分析层的坑见 `verification-criteria.md`。**本文件只讲工具与流程本身的雷** —— 这些会让你的数据在你不知情的情况下出错。

---

## 一、数据被静默覆盖（最贵的一个）

**守护进程每次 `/harvest` 都会把完整结果写入 `<outDir>/<id>.json`。**

如果你用 curl 把响应存到**同一个文件名**：

```bash
curl "http://127.0.0.1:8899/harvest?id=similarweb" -o out/similarweb.json   # ❌ 覆盖守护进程的输出
```

**后果**：某次重跑时额度已被打满，结果全是 `- -`，于是**唯一一份完整数据被永久覆盖**。

**规则**：
- 要么不传 `-o`，要么写到别的名字
- **对"只成功过一次"的关键数据，抓完立刻另存一份带时间戳的副本**：

```bash
cp out/similarweb.json "out/similarweb.$(date +%Y%m%d-%H%M).json"
```

---

## 二、HTTP 响应里的 text 是**截断副本**

守护进程返回的 `text` 字段会按 `config.defaults.responseTextLimit` 截断（默认 12000 字符），**大结果会被腰斩**。

**完整结果始终在 `out/<id>.json` 里。**

→ **拿到大结果时读文件，不要读 HTTP 响应。** 典型症状是"结果看起来只有一半"。

---

## 三、profile 锁：为什么必须"进程内取数"

Chrome 的 profile 目录**同一时刻只能被一个进程持有**。

- 若"登录浏览器"与"抓取脚本"是两个进程 → 必然抢锁
- **不要走 `--remote-debugging-port` + CDP 的路线**：它与 `launchPersistentContext` 冲突

所以架构上让**同一个进程**既持有 context、又提供取数 HTTP 接口。

---

## 四、无头模式的稳定性

**有头模式是设计用法**（用户要手动登录），此时窗口被关闭 = 主动结束，符合预期。

**无头模式（`--headless`）用于验证会话是否还在**，但要注意：

- **`viewport: null` + `--start-maximized` 会让 headless 直接退出** → 无头时必须给固定 viewport
- **页面数归零时 context 会退出** → 留一个常驻页（`about:blank`）兜底
- 本装置的 `login-console.js` 已内置这两处防护

**⚠️ 如果你在沙箱化的一次性命令里启动守护进程，命令结束时进程可能被回收。**
→ 守护进程要在**真实终端**里跑；或把"启动 + 取数"放在同一条命令内。

---

## 五、改了捕获器不生效 / 报错伪装

**改 `harvest.js` 后不需要重启守护进程** —— 每次 `/harvest` 都会 `delete require.cache` 重新载入。

**⚠️ 但语法错误会被伪装成"抓取器运行错误"**：错误信息看起来像抓取失败，实际是 JS 解析失败。

**规则：每次改完 harvest.js，先做语法检查再打接口。**

```bash
node --check harvest.js
```

---

## 六、超时导致"整体失败且不落盘"

**单次 harvest 不要塞太多 URL**（经验上限 **4–5 个**）。子域名连接挂起会把耗时拖到 45s × N，超过客户端超时后：

- 请求失败
- **而且结果不落盘** → 你会以为"这个抓取器不工作"

**对策**：分批跑；或把长任务放后台执行，之后读 `out/`。

---

## 七、限流被读成"没有数据"

**接口返回非 200 且 body 为空时，如果代码只返回 `{n: 0, items: []}`，限流就会被静默读成"零结果"。**

**规则**：抓取器**必须把 `status` 一并回传**。查询之间留间隔（Reddit 实测需 5 秒）。

**症状自查**：如果一次枚举里"大部分查询都返回 0"，先怀疑限流，不是"真的没有"。

---

## 八、选择器失效 → 静默取空

**不要去猜选择器。** 页面改版后，错误的猜测往往**返回空数组而不是报错**。

**流程**：
1. 先用 `entry_discover` / `list_pages` / 页面探针看清真实 DOM 结构
2. 再写提取规则
3. 抓取器返回结果里**始终带上 `title` / `finalUrl`**，便于发现"跳转到了登录页/404 而你以为抓到了内容"

**判据**：结果为空时，先看 `finalUrl` 对不对，再看 `text.length` —— **不要直接下"没有数据"的结论**。

---

## 九、锚点会打断 SPA

给 SPA 站（SimilarWeb 这类）加 `#section-anchor` 会**打断渲染**，导致面板取不到数据。

**用 plain URL + 慢滚动**。

---

## 十、引号与编码

- **macOS 的 BSD grep 不支持 `\|` 作为 BRE 交替** → `grep "a\|b"` 会**静默返回空**（不报错），极易误判为"内容不存在"。**用 `grep -E "a|b"`。**
- 编辑含 HTML 实体的文本时（如 `&#x4F5C;` 代替"作"），精确匹配会失败 → 遇到匹配不上先读原文。
- 写代码/配置/命令时统一用 ASCII 直引号；仅自然语言内容可用弯引号。

---

## 十一、报告文件被外部覆盖

**症状**：改完存盘了，下一次检查发现行数回退、整节消失。

**成因**：本地编辑器里开着旧版本，保存时用旧缓冲区覆盖磁盘。

**对策**：
1. 改前先记 `wc -l` 与 mtime 基线
2. **改完立刻 `cp` 一份带时间戳的副本到安全目录**
3. 每轮用**该轮独有的关键词**做自检：

```bash
# 该轮新增的专有名词，应该能搜到
grep -c "该轮独有词" 报告.md
```

**这条自检极其有效** —— 几个关键词同时返回 0，就能立刻定位到丢失范围。

**并主动提醒用户关闭编辑器里的旧版本。**

---

## 十二、沙箱与网络

- **直连 curl 在某些沙箱内被阻断**（表现为连接被拒）→ 走浏览器或内置抓取通道
- **后台进程可能被沙箱在命令结束时回收** → 长任务要放在同一命令内完成，或在真实终端里跑
- 本地 HTTP 调用失败时，先确认**守护进程还活着**（`lsof -nP -iTCP:<port> -sTCP:LISTEN`），再怀疑代码

---

## 十三、自查清单（每次交付前过一遍）

- [ ] 单次 harvest 的 URL 数是否 ≤ 5？
- [ ] 是否用 `curl -o` 覆盖过 `out/` 里的文件？
- [ ] 关键数据是否有带时间戳的副本？
- [ ] 改过 `harvest.js` 后是否跑过 `node --check`？
- [ ] 结果为空的抓取器，是否确认过是"真没有"而不是"限流/选择器失效"？
- [ ] 枚举类抓取器是否回传了 `status`？
- [ ] 报告里每个数字是否都标了**口径与来源**？
- [ ] "拿不到"的数据是否都列进了缺口表（而不是估一个数填上）？
- [ ] 报告是否有安全副本？
