# 竞品增长研究流程

六个阶段，**顺序不能乱**。跳步会得到看起来很完整、但结论站不住的报告。

---

## 阶段 0 · 定义研究对象与口径

在动手取数前先把这几件事写下来，否则后面每拿到一个数字都要重新纠结：

| 要定的事 | 说明 |
|---|---|
| **主域名** | 用于 SimilarWeb、sitemap、外链归因。多域名要分清主站与落地页 |
| **品牌词变体** | `chatcut` / `chat cut` / `chatcut ai` 要去重，否则声量会重复计算 |
| **品类词** | 用于「品牌 vs 品类」对照 —— 这是判断渠道角色的关键，见 `verification-criteria.md` |
| **竞品词** | 对照曲线用 |
| **官方账号清单** | 每个平台的官方号/创始人号，用于第一方归因 |
| **时间窗** | 至少覆盖"破圈前 6 个月 ~ 现在"，否则看不到需求的起点 |

把这六项填进 `scripts/config.js`，全部抓取器都从这里读参数。

---

## 阶段 1 · 公开检索：先建立渠道地图

**目的**：知道"可能有哪些渠道"，不是"每个渠道有多少量"。

用搜索引擎、平台站内搜索、第三方目录，把所有出现该产品的渠道列出来。这一步**不需要精度**，需要的是**覆盖面**。

产出物：一张渠道清单，按 12 大类分组（自有阵地 / 榜单 / 社区 / 视频 / 图文 / 科技媒体 / 社交 / 播客 / 搜索SEO / 私域 / 集成生态 / 线下）。

> **⚠️ 这一步最大的风险是把"检索为空"当成"渠道不存在"**。
> 实测过的例子：用普通网页搜索找某产品在 Reddit 上的内容，只看到零星几条；换成平台原生 JSON 接口 + 多查询枚举后，出来 **28 帖**。
> **下"No Data"结论之前，先升级检索手段。** 详见 `pitfalls.md`。

## 阶段 2 · 登录态取数：把量级拿回来

公开检索能告诉你"有内容"，但拿不到**评论数、票数、成员数、播放量**这些决定性字段。这些几乎都需要登录态。

### 建立取数装置

```bash
cd scripts
npm i playwright-core        # 仅一个包
npm run smoke                # 先跑冒烟测试，确认环境 OK
npm run console              # 启动登录控制台，窗口里手动登录
```

控制台做的事：起一个**可见 + 持久化**的 Chromium，Cookie 落在 profile 目录，**登录一次后长期复用**。同时起本地面板显示各平台登录状态。

### 为什么要"进程内取数"

Chrome 的 profile 目录同一时刻只能被一个进程持有。如果"登录用的浏览器"和"抓取脚本"是两个进程，必然抢锁。

所以本装置让**同一个进程**既持有浏览器、又对外提供取数接口：

```bash
curl "http://127.0.0.1:8899/harvest-list"                    # 列出所有抓取器
curl "http://127.0.0.1:8899/harvest?id=probe_text&arg=<url>"  # 执行并落盘
```

改 `harvest.js` 后**不需要重启**（每次调用都会重新载入）。

### 取数的三条纪律

1. **不要猜选择器。** 先跑 `entry_discover` / `list_pages` 看清页面结构，再写提取规则。
2. **先固定口径，再比数字。** 同一个"声量"指标在不同工具下能差 50 倍（标题口径 vs 全文口径）。**不写口径的数字没有意义。**
3. **单次不要塞太多 URL。** 超时会导致整体失败**且不落盘**。分批跑，或改用后台执行。

## 阶段 3 · 来源归因：这些内容是谁发的

这是最容易被跳过、但决定结论质量的一步。同一个"有 100 条内容"的现象，背后可能是完全不同的三种事：

| 类型 | 识别特征 | 怎么验证 |
|---|---|---|
| **第一方** | 账号名 = 品牌/创始人；简介挂**渠道专属追踪链接** | 看简介里的 `域名/r/<渠道>-<随机码>` |
| **付费 KOL（联盟）** | 链接带 `?fpr=<用户名>` 等联盟参数 | FirstPromoter 等参数一眼可辨 |
| **付费 KOL（平台备案）** | 平台接口字段标注（如 B站 `is_union_video`） | 接口字段 |
| **铺量号 / 操纵** | 文本跨账号重复；账号非垂类；**账号被平台封禁** | 见 `verification-criteria.md` 的账号级取证 |
| **真实 UGC** | **必须做账号级验证**，不能只看标题 | 四步法，见 `verification-criteria.md` |

> **关键动作：给对照组做身份核查。**
> 如果你要拿"别的产品"当"正常参照"，**先确认它和你研究的对象不是同一来源**——否则基线是循环论证。

---

## 阶段 4 · 讨论度：内容引发了多大反响

区分三件事：

- **声量**（铺了多少）≠ **讨论度**（引发多大反响）≠ **转化**（带来多少用户）
- 同一个月发了 25 条视频但没有一条播放过 1,375 —— **那 25 条是无效声量**

要拿的字段：浏览 / 点赞 / 评论 / 转发 / 收藏 / 投票。

> **收藏常常 > 点赞，这是工具类内容的典型特征。** 用户不点赞，但会收藏备用。**评估工具类内容时收藏率比点赞率更能反映真实价值。**

---

## 阶段 5 · 交叉验证与归因修正

**这一步决定报告能不能信。** 至少做三种交叉：

1. **多源交叉**：同一指标用两个工具各取一次，**口径不同要写明**，否则会制造假矛盾。
2. **时间交叉**：把"渠道动作的时间线"与"需求曲线"对齐 —— 见阶段 6。
3. **反向检验**：主动找**能证伪自己结论**的证据。

必查的四个陷阱：

- **帖子浏览量 ≠ 网站访问量**（差 1–2 个数量级）
- **IP 国别归因受 VPN 污染**（不能直接当市场规模）
- **Direct 不是一种渠道**，是归因失败的垃圾桶
- **互动率指标要先拿"同类型 + 同量级"的 cohort 做基线**

详见 `verification-criteria.md`。

---

## 阶段 6 · 需求时序：判断渠道是"造需求"还是"接需求"

**这是最能拉开结论质量的阶段。** 大多数竞品报告停在第 5 阶段，所以只能给出"哪个渠道大"，说不出"哪个渠道有用"。

做法：把三条线放进同一张表。

| 序列 | 来源 | 说明 |
|---|---|---|
| **搜索需求** | Google Trends（长历史） | **独立于站方自述**，是唯一能测"需求本身"的公开信号 |
| **社媒动作** | 官方账号全量发帖量 | 按精确时间戳聚合到月 |
| **内容池供给** | `sitemap.xml` 的 `<lastmod>` | 只统计新增页面 |

然后看三件事：

1. **需求的绝对时序**：渠道动作在需求**之前**还是**之后**？
2. **内容产量与需求是否同步**？产量高而需求低 → 该渠道不产生需求
3. **搜索词的性质**：品牌词占比高 → 在收割已有认知；品类词占比高 → 在捕捉新需求

**典型发现（可迁移的结论形态）**：

> 内容池比需求出现得早 9 个月，而需求在前 30 个月**始终为零**；
> 需求的两个峰精确落在两次"社媒爆点"的**当周**；
> 而内容产量最高的那个月，需求是全期最低。
>
> → **增长（增量）靠事件，留存（存量）靠内容池。**
> → **"SEO 是第一渠道"是结果指标，不是增长原因。**

**最大的机会往往在这里浮出来**：如果品类词的搜索量远大于品牌词，而研究对象主要在吃品牌词 —— 那就是它（和你）真正的机会池。

## 交付物清单

| # | 交付物 | 关键要求 |
|---|---|---|
| 1 | **渠道地图** | 12 大类全覆盖，含"未使用"的渠道 |
| 2 | **逐渠道数据表** | 每个数字标注口径与来源 |
| 3 | **来源归因表** | 第一方 / 联盟 KOL / 铺量 / 真实 UGC 分开列 |
| 4 | **流量结构** | 渠道占比 + 社媒下钻 + 国家分布，含口径警告 |
| 5 | **需求时序表** | 三条线对齐，含结论与反例 |
| 6 | **可复用打法清单** | 应该做的 / 不该做的 / 看起来该做但低效的 |
| 7 | **数据缺口表** | 拿不到的都列明，**不做估算填充** |
| 8 | **原始链接附录** | 关键结论挂可点开的原始素材 |
